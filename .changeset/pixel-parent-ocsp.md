OCSP revocation for wrap-mode parents. A third-party capture (Pixel) has no row in the issued-certificates ledger, so until now a capture signed with a certificate its vendor had revoked — the public Pixel forgery is one — passed the Stage 1 checks. Each trust source can now declare `revocation: { ocsp_hosts }` in `trust-sources.yaml`; the Pixel entry names `http://c2pa-ocsp.pki.goog`, the responder its leaf certificates publish.

The union of every source's `ocsp_hosts` is handed to c2pa-rs as `core.allowed_network_hosts` on every read — the whole of the engine's outbound allow-list, empty when nothing is declared, which blocks every request — and `verify.ocsp_fetch` turns on only when the new `NETWORK_REVOCATION` env var is `true` and a responder is declared. Production must set the variable explicitly to `true` or `false` (the `ATTESTATION_REQUIRED` rule), and must set it on the service before deploying this image: the deploy keeps the existing env, and an image booting without it fails the startup probe. Elsewhere it defaults to off, so tests, local runs and the crJSON conformance harness make no network request.

Policy: `signingCredential.ocsp.revoked` (and `.unknown`) anywhere in the store's `validation_status` maps to `UNTRUSTED_ISSUER`, `category: ocsp` — not `KEY_REVOKED`, which makes the app discard the uploader's own key. For a source that declares responders, the profile requires the responder's `notRevoked` answer in the `success` bucket of the capture's own ingredient row (located by `ingredientAssertionURI`; the active manifest's codes are never consulted, and a response stapled into the manifest files as `informational`, so it is not evidence) and otherwise rejects as retryable `VERIFIER_UNAVAILABLE`, `category: ocsp`, naming the bucket and codes it saw. The gate runs last among the structural checks and ahead of every datastore read. c2pa-rs's HTTP client has no timeout, so a read with OCSP fetch on is bounded at 10 s. RealReel's own certificates are never checked over the network; the loader refuses a `revocation` block on a `realreel`-profile source, and refuses unknown keys in the block.

On the pinned engine (c2pa-rs 0.90.22) only the leaf certificate is queried and the responder's certificate is not chained to a trust anchor, so a party on the path to the responder could forge a `good` answer; c2pa-rs 0.91 closes both (#2615, #2542, #2616) and is the next engine bump once a matching `c2patool` ships.

Docs: `README.md` (onboarding: read the AIA OCSP host off a vendor sample leaf), `DEPLOY.md` (`NETWORK_REVOCATION`, deploy ordering), `OPERATIONS.md` (responder-outcome table, the residual), `TRUST_ARCHITECTURE.md`. The verifier logs its effective network posture at startup.
